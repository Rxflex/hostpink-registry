# hostpink-registry

Официальный реестр плагинов для [hostpink](https://host.pink/tui/), терминального клиента [host.pink](https://host.pink).

Плагин — это скрипт сообщества из чужого git-репозитория: установщики Remnawave, Решала, бэкапы, проверки доступности и бенчмарки. Реестр ничего не хранит у себя, он только описывает, **какой файл, с какого коммита и с каким хэшем** запускать.

```sh
curl -fsSL host.pink/tui | sh      # Linux, macOS, FreeBSD
irm host.pink/tui | iex            # Windows PowerShell
```

## Как это работает

1. Клиент берёт `hostpink-registry.json`: с зеркала `host.pink/plugins.json` или, если оно недоступно, прямо отсюда.
2. Каждый плагин закреплён на полном SHA коммита (`ref`). Файлы скачиваются по неизменяемому адресу `raw.githubusercontent.com/<repo>/<ref>/<path>` и сверяются по SHA-256 из реестра. Не совпало — запуск отменяется.
3. Перед запуском клиент показывает репозиторий, коммит, файлы с хэшами, точную команду и предупреждения:
   - **нужен root** — команда пойдёт через `sudo`;
   - **сам докачивает код** — скрипт при запуске скачивает свежие файлы из своей ветки, и закреплён только загрузчик. Это честное предупреждение: так устроены многие установщики, и реестр не может это исправить за автора.
4. Обновления плагинов никогда не ставятся молча: новый коммит попадает в реестр только через pull request.

## Добавить плагин

1. Сделай форк, положи файл `plugins/<id>.json`:

```json
{
  "id": "my-tool",
  "title": "Мой инструмент",
  "author": "github-логин автора скрипта",
  "repo": "owner/repo",
  "category": "Проверки",
  "description": "Одна-две фразы: что делает и где запускать.",
  "platforms": ["linux"],
  "files": [{ "path": "install.sh" }],
  "actions": [
    { "id": "install", "title": "Установить", "run": "bash install.sh" },
    { "id": "status", "title": "Статус", "run": "bash install.sh status" }
  ],
  "source": "https://ссылка/на/обсуждение/или/документацию"
}
```

2. Запусти `node scripts/registry.mjs --pin`: он закрепит плагин на свежем коммите, посчитает хэши файлов и сам отметит `needs_root` и `fetches_latest`. Затем `node scripts/registry.mjs`, чтобы пересобрать `hostpink-registry.json`.
3. Открой pull request. CI проверит формат и то, что `hostpink-registry.json` собран.

Поля:

| Поле | Что это |
|---|---|
| `id` | `a-z`, `0-9`, дефис; совпадает с именем файла |
| `repo`, `ref` | репозиторий на GitHub и полный SHA коммита (ставит `--pin`) |
| `platforms` | `linux`, `darwin`, `windows`, `freebsd`; на остальных ОС клиент не даст запустить |
| `files` | файлы, которые скачиваются и проверяются; команды запускаются в каталоге с ними |
| `actions` | что можно сделать; `run` разбивается по пробелам, без shell-синтаксиса |
| `needs_root` | запускать через `sudo`; `--pin` ставит сам, если скрипт проверяет `EUID` |
| `fetches_latest` | скрипт докачивает код из ветки; ставит `--pin` |
| `featured` | показывать в «Популярных плагинах» на главном экране hostpink; ставят мейнтейнеры реестра |

Обновить закрепление всех плагинов: `node scripts/registry.mjs --pin --update`, посмотреть дифф, закоммитить.

## Свой реестр

Любой репозиторий с `hostpink-registry.json` в корне — тоже реестр. Подключается одной командой:

```sh
hostpink registry add github.com/owner/repo
```

Плагин из одного репозитория без реестра: положи в корень `hostpink.toml` с теми же полями и выполни `hostpink add github.com/owner/repo`. Клиент закрепит его на текущем коммите и запомнит хэши.

## Безопасность

Плагины запускают чужой код, часто от root. Реестр снижает риск (закрепление на коммите, хэши, ревью через PR), но не превращает чужой скрипт в проверенный. Читай код перед запуском: в клиенте это клавиша `v`. Если нашёл вредоносный плагин, открой issue — его уберут из реестра.
